# Стартовое сообщение для нового чата

Продолжаем разработку игры **MOSCOW**.

Актуальная база проекта — архив **MOSCOW-v0.3.1-handoff.zip**. Используй только его как исходник и не возвращайся к старым версиям.

## Что уже есть

- React + Vite frontend.
- Cloudflare Worker backend.
- D1 database `moscow-city-db`.
- Durable Object `EconomyCoordinator`.
- Аккаунты FREE/FUNDED.
- Стартовый баланс 200 000 ₽G, он NON_WITHDRAWABLE.
- TEST SOL deposit/withdraw.
- SOL ↔ ₽G exchange.
- Ledger, transactions, idempotency.
- Player progress, catalog, inventory, purchases.
- Покупка `starter_phone` за 15 000 ₽G.
- Первый игровой vertical slice уже собран в коде.
- GitHub: `sandboxtrade/MOSCOW`, ветка `main`.

## Визуальная часть

Мы отказались от технического CSS-прототипа как финального вида и перешли к полноценным игровым ассетам.

Утверждённый фон первой комнаты лежит здесь:

`web/public/assets/apartment-room-approved.png`

Это пиксельная московская квартира ночью без персонажей, HUD и интерфейса. Считай её текущей визуальной базой первой сцены.

## Как теперь работаем

Не тратить время на долгую невидимую инфраструктуру. Разрабатывать вертикальными кусками: **визуал → взаимодействие → минимальный backend → проверка**.

Не присылай мне огромные куски кода для ручного копирования. Правь проект целиком и возвращай готовый ZIP с аккуратной структурой. Не добавляй `node_modules`, `dist`, `.wrangler` и прочий генерируемый мусор.

Старые миграции `0001`–`0003` не переписывать. Следующее изменение БД — только новой миграцией `0004_...sql`.

## Следующая задача

Проработать **первую игровую комнату визуально** поверх утверждённого фона.

Нужно:

1. встроить утверждённый фон в `ApartmentScene`;
2. убрать из сцены всё, что конфликтует с готовым фоном;
3. сделать слои поверх фона: игрок, проводник, телефон, дверь/выход, рабочее место;
4. сохранить HUD, квесты и диалог отдельными UI-компонентами;
5. сделать интерфейс визуально единым с референсом: тёмно-синий игровой HUD с яркими голубыми акцентами, но без перегруза;
6. mobile-first, основной формат вертикальный;
7. после изменений собрать готовый архив следующей версии.

Сначала прочитай структуру проекта и `PROJECT_STATE.md`, `docs/FILE_MAP.md`, `docs/VISUAL_DIRECTION.md`. Затем сразу начинай работу, не спрашивая меня повторно о том, что уже есть в архиве.
